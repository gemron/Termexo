# 第三方通知总开关

桌面顶部“远程访问”旁的“第三方通知”开关控制所有外部通知渠道是否允许发送。当前已接入桌面微信；后续渠道共用此总开关。各渠道仍需在各自设置中单独启用并配置目标、项目范围和事件类型。

关闭总开关会暂停新的外部通知，并丢弃尚未开始发送的前端排队通知；已经开始发送的操作可能完成。重新开启按各渠道原有配置恢复，不补发暂停期间的事件，不改变渠道开关、目标或事件设置。应用内提醒和系统桌面通知保持原有行为。

总开关以 `third-party-notifications.v1` 独立持久化，升级时默认允许发送以保留原有渠道行为（不会启用原本关闭的渠道）。读取失败时停止发送；保存失败保留原状态，并显示错误。远程客户端无法修改本机通知设置。

后端 `ensure_enabled` 是所有外部渠道发送前的共同检查入口，MCP 发起的微信通知也执行此检查。新渠道必须接入此前后端检查，不自行维护总开关。前端在暂停期间继续消费事件，以免恢复后重放历史提醒。

各渠道可复用 `content::format_notification` 内容模板。通知显示本机时间（含日期、秒和 UTC 偏移）、项目、任务，以及可用的会话、Agent、模型、分支信息；并按事件类型给出下一步提示。没有关联会话时省略相关字段，任务名称缺失时优先使用关联会话名。正文时间与投递记录一致，元数据整理成有长度上限的单行文本。

```text
[Termexo · 任务完成]
通知时间：2026-10-25 02:10:30 UTC+08:00
项目：示例项目
任务：构建项目
会话：Codex CLI 3
Agent：Codex CLI
模型：example-model
分支：main

任务已完成，请回到 Termexo 查看结果。
```

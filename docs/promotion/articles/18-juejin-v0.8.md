# 让手机接管桌面上正在跑的 Agent 终端：Termexo V0.8 远程访问的三个工程决定

场景很具体：Claude Code 正在做一个跨模块重构，跑到一半停在「等待授权」，要你确认一次写入。而你在客厅、在通勤、在另一间办公室。那台 Windows 机器还开着，PTY 还活着，进程在等一个回车——只是你不在桌前。

以前的解法是远程桌面，或者干脆等回去再说。V0.8 给 Termexo 加了远程访问：在设置里打开之后，同一局域网或 VPN 内的手机、平板、另一台电脑用浏览器打开就是完整工作台，同一批工作空间、同一批终端，**实时读写桌面上正在运行的那一批 PTY 进程**。不是只读镜像，也不是另开一套会话——手机上敲进去的字符，进的是同一个进程的 stdin。

![手机通过远程访问打开工作台](../assets/termexo-remote-v0.8.png)

这篇写的是把这件事做成的过程中，三个不太好绕开的决定。

## 一、不写第二套后端：远程请求走桌面自己的命令表

桌面端前端和 Rust 之间已经有一张完整的命令表。远程如果另起一套 HTTP API，等于把每条命令的参数校验、序列化和错误信息再实现一遍，而且从第一天起就会开始漂移：桌面端改了一个字段，远程端要过很久才有人发现没跟上。

所以选的是桥接：从 socket 收到的请求被转成 `InvokeRequest` 交给主 webview，走**同样的命令、同样的反序列化**。远程端和本地端执行的是同一份代码路径，不存在两套行为。

代价必须说清楚。Tauri 的 ACL 在本地来源下不覆盖应用命令，而这条桥接必然声称自己是本地来源——也就是说框架层的权限系统在这条路径上帮不上忙，**显式白名单成了唯一的授权边界**。既然是唯一边界，它就得是「默认拒绝、逐条放行」。被明确挡在外面的包括：npm 自更新、原生文件读写，以及修改远程访问设置本身。最后一条尤其重要——远程端不能给自己扩权，不能换发令牌，不能把口子开得更大。

这里没有什么聪明写法，就是一张需要人维护的名单。好处是可读、可审计；风险是新增命令时有人忘了想清楚它该不该进这张表。这是我们接受的维护成本，而不是假装它不存在。

## 二、手指在终端上滑不动：xterm 6 把缓冲区画在了 canvas 上

第一版远程能连上、能输入，但手机上滑不动终端。原因不复杂：xterm 6 把缓冲区画在 canvas 上并自绘滚动条，DOM 里根本没有一个「可滚动元素」让浏览器的触摸滚动去命中。手指按下、拖动、松开，浏览器找不到滚动容器，于是什么都没发生。

修法是把触摸拖拽翻译成 xterm 认识的语言：**拖拽过程中合成滚轮事件交给 xterm 分发**。普通缓冲区直接滚动；Claude Code、OpenCode 这类全屏 TUI 则按它们自己订阅鼠标上报的方式收到滚轮事件，行为与在桌面上真的拨滚轮一致。松手后带惯性。

关键是「交给 xterm 分发」，而不是自己去改 viewport 的位置。终端有正常缓冲区和备用屏幕两种状态，全屏 TUI 在备用屏幕里自己管滚动——绕过 xterm 直接挪画面，只会在 TUI 里得到一屏错位。

同一类问题还有一个：浏览器里新建终端原先要弹 `window.prompt` 选目录，而部分移动浏览器直接屏蔽它，结果是远程客户端根本建不了终端。现在换成应用内对话框，并预填当前工作空间目录。桌面上「凑合能用」的交互，搬到远程往往不是体验差一点，而是功能直接不可用。

## 三、一个 PTY 只有一个尺寸

这是最没得商量的一条。PTY 的窗口大小只有一组行列数，跑在里面的 TUI 按这组数字排版。所以当同一个终端被两块屏幕同时看着时，不存在「各看各的尺寸」。

Termexo 的选择是：**尺寸属于正在使用的那一端**。在电脑上操作就用电脑的宽度，拿起手机操作就换成手机的，切回电脑再变回去。其余客户端渲染同一张网格，窗口装不下时横向平移，而不是重排。

这条规则有一个必须写在明面上的副作用：在手机上打开终端，桌面端的列数会跟着变。它不是 bug，是这条约束的直接结果。我们宁可明确地把控制权交给正在操作的那个人，也不想让两端互相抢尺寸，或者悄悄给远程端降级成一个只读视图。

## 手机端布局，以及会话级 Git 视图

640px 以下，分屏布局收成单终端；两侧面板浮在工作区之上，而不是占走一列——小屏幕上任何一列都太贵。控件放大到手指可点的尺寸，顶栏右侧的工具收进一个「更多」菜单。

同一版还有一条独立的线：Git 视图跟随**当前终端**，以该终端启动时的 HEAD 为基线，显示这次会话动过哪些文件、提交了什么，任意文件可看单栏或双栏 Diff 并显示 +N / −N 行数。停留在该视图时会持续读取仓库，不用手动刷新；切换当前终端或读取失败都不会把你弹回终端视图，读不到时会说明原因；离开再回来仍停在原来的文件和 Diff 布局上。原生会话文件（`~/.claude/projects/**/*.jsonl`、`CODEX_HOME/sessions`）始终只读。

## 边界，先说清楚

- **仅 Windows**，没有 macOS / Linux 版本。
- 远程访问面向可信网络（家庭局域网或 VPN）。默认自签名 HTTPS，浏览器会提示不安全，每台设备需要手动确认一次。
- **令牌等同于这台电脑上 Termexo 的完整控制权**，可以随时在设置里换发。
- 远程端不能修改远程访问设置本身，也不能导入导出网络配置或触发 npm 自更新。
- 终端只有一个尺寸，以最后一次调整为准。
- 任务看板不同步，任务保存在各自浏览器本地。

远程访问是 Termexo 唯一一条对外连接，由用户自己打开、自己发令牌、随时可关。没有 Termexo 账号，没有云端中转。

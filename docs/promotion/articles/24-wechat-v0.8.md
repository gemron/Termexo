## 正文

### 一、它在等你点一下，而你在客厅

用过编程 Agent 的人大概都遇到过这个场面。

你让它去改一个模块，它跑了几分钟，停在一句「是否允许写入这个文件」。

它不会往下走了。而你此刻在客厅、在会议室、在楼下便利店。等你回到电脑前，Agent 已经空等了半小时。

问题不在于 Agent 不够聪明，而在于「确认」这个动作被钉死在那块屏幕前。

Termexo V0.8 想解决的就是这一件事。

### 二、远程访问：不是镜像，是同一批终端

在设置里打开远程访问之后，同一局域网或 VPN 内的手机、平板、另一台电脑，用浏览器就能打开完整的工作台。

同一批工作空间，同一批终端。你在手机上敲的每一个字符，进的是桌面上正在运行的那个 PTY 进程。

它不是只读的画面镜像，也不是另开一套会话——回到电脑前，光标就停在你刚才留下的位置。

默认走自签名 HTTPS，凭访问令牌进入。设置面板可以显示令牌、生成二维码，也可以随时更换令牌。

> 配图：`![手机远程打开工作台](../assets/termexo-remote-v0.8.png)`
> 图注：手机通过远程访问打开的工作台，叠在它所连接的桌面端之上

想多说一句实现上的取舍。

远程访问没有另写一套后端。从 socket 收到的请求会被转成 `InvokeRequest` 交给主 webview，走的是桌面端自己那张命令表、同一套反序列化。

代价是 Tauri 的 ACL 在本地来源下不覆盖应用命令，而这层桥接必然声称自己来自本地——所以**显式白名单是唯一的授权边界**。npm 自更新、原生文件读写，以及修改远程访问设置本身，都在白名单之外，远程端调不动。

### 三、手机上真的能用，靠的是几处不起眼的改动

「能打开」和「能用」中间隔着不少细节。

**手指滚动终端。** xterm 6 把缓冲区画在 canvas 上、滚动条也是自绘的，手指拖拽本来触达不到任何可滚动元素。现在拖拽会合成滚轮事件交给 xterm 分发：普通缓冲区直接滚动，Claude Code、OpenCode 这类全屏 TUI 则按它们自己订阅的方式收到滚轮上报，行为和桌面滚轮一致，松手之后还有惯性。

**手机端布局。** 640px 以下，分屏布局收成单终端，两侧面板浮在工作区之上而不是走掉一列，控件放大到手指点得中的尺寸，顶栏右侧的工具收进一个「更多」菜单。

**新建终端不再依赖系统对话框。** 浏览器里新建终端原先要弹 `window.prompt` 选目录，部分移动浏览器直接屏蔽它，结果是远程客户端根本建不了终端。现在换成应用内对话框，并预填当前工作空间目录。

还有一条得说在前面：**一个 PTY 只有一个尺寸**。所以它属于「正在使用的那一端」——在电脑上操作就用电脑的宽度，拿起手机操作就换成手机的，切回来再变回去。其余客户端渲染的是同一张网格，窗口装不下时横向平移。

### 四、另一条线：Git 视图跟着当前终端走

V0.8 的另一处改动在 Git 视图。

它现在跟随**当前终端**，并以该终端启动时的 HEAD 为基线：这次会话动过哪些文件、提交了哪些内容，一目了然。任意一个文件都能看单栏或双栏 Diff，带 +N / −N 行数。

停留在这个视图时它会持续读取仓库，不用手动刷新。切换当前终端或者读取失败都不会把你弹回终端视图；读不到的时候会说明原因；离开再回来，仍停在原来的文件和 Diff 布局上。

原生会话文件（`~/.claude/projects/**/*.jsonl`、`CODEX_HOME/sessions`）始终只读。

> 配图：`![会话级 Git 视图](../assets/termexo-git-v0.8.png)`
> 图注：变更文件、提交图谱与 Diff，都以当前终端这次会话为范围

### 五、V0.8.1：把新用户看到的第一屏修好

这一版还修了一个我自己看着都难受的问题。

此前新安装会种下三个示例工作空间，目录指向一个谁的机器上都不存在的路径，里面的 Agent 终端还会去恢复根本不存在的 session id。于是新用户看到的第一屏，是两个报 `Invalid session ID` 的终端。

现在改成从空开始。工作区那块会说明什么是工作空间、头三步做什么、内容都留在本机，并给一个直接创建的按钮。

顺带归位了两个操作：

- 「新建」从窗口工具栏移回标签栏。它原先和工作区开关并列，但它只是往某条标签栏加一个标签，不该摆在工作区级别的位置。现在它接管标签栏里的 `+`，Agent 菜单一并带过去，按钮紧跟最后一个标签，菜单里 Agent 排在普通 Shell 上面。
- 新建完会直接打开新终端。此前只设置活动终端，而任务看板和 Git 视图根本不画终端，从这两个视图新建时，终端建好了却看不见。

远程访问设置页也重排了：监听地址与端口并排，复制按钮贴着链接，总开关与 HTTPS 选项分开，并带上「已连接设备」计数。

> 配图：`![V0.8 桌面工作台](../assets/termexo-workbench-v0.8.png)`
> 图注：V0.8 的真实桌面工作台，双终端网格与真实命令输出

### 六、边界，直接说清楚

- **仅 Windows。** 没有 macOS / Linux 版本。
- 远程访问面向可信网络（家庭局域网或 VPN）。自签名证书会让浏览器提示不安全，每台设备需要手动确认一次；**令牌等同于这台电脑上 Termexo 的完整控制权**，别往公开群里发。
- 远程端不能修改远程访问设置本身，也不能导入导出网络配置或触发 npm 自更新。
- 终端只有一个尺寸，以最后一次调整为准；在手机上打开终端，会同时改变桌面端的列数。
- 任务看板不同步，任务保存在各自浏览器本地。
- Codex 第三方 Endpoint 需要兼容 Responses API，不承诺所有第三方模型都兼容。
- 应用退出后被终止的系统进程不会「假装恢复」，历史会话需要在会话中心显式恢复。

本地优先不等于模型请求不联网：Claude Code、Codex、OpenCode 仍然按你选择的供应商访问模型服务。Termexo 做的是本地编排，远程访问是唯一一条对外连接，而且由你自己打开、自己发令牌、随时可关。

### 七、怎么试

Termexo 面向 Windows 10/11 x64，MIT 许可证开源。装好 Node.js 18.18+ 和 WebView2 之后，一条命令就能跑起完整桌面应用：

```
npx termexo@latest
```

也可以从 GitHub Release 下载 EXE 或 MSI 安装包。

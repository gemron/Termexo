# Agent 卡在授权那一步，而你已经离开工位

用 Claude Code 或 Codex 跑长任务的人大概都遇到过：交代完一件事去做别的，回来才发现 Agent 早就停在
「是否允许修改这个文件」上，中间那段时间什么都没发生。

这不是模型的问题，也不是终端的问题。是那台跑着 Agent 的电脑，只有坐在它前面才能回话。

Termexo 的 V0.8 想解决的就是这一件事。

![手机通过远程访问打开的 Termexo 工作台，叠在它连接的桌面端之上](../assets/termexo-remote-v0.8.png)

## 打开远程访问，工作台就跟着你走

在设置里打开远程访问后，同一局域网或 VPN 内的手机、平板、另一台电脑，用浏览器就能打开完整工作台。

需要强调的是它**不是只读镜像**：你看到的是同一批工作空间、同一批终端，读写的是桌面上正在运行的
同一批 PTY 进程。在手机上敲的字会进到那个终端里，桌面端同步显示；Agent 在等的那次授权，也能在手机上
放行。

默认走自签名 HTTPS，凭访问令牌进入。设置面板里可以显示令牌、生成二维码、随时更换。

## 手机上真的能用，而不只是能打开

「能打开」和「能用」之间隔着几件很具体的事，V0.8 逐个处理了：

**终端能用手指滚动。** xterm 6 把缓冲区画在 canvas 上并自绘滚动条，手指拖拽本来触达不到任何可滚动
元素——页面纹丝不动。现在拖拽会合成滚轮事件交给 xterm 分发：普通缓冲区直接滚动，Claude Code、
OpenCode 这类全屏 TUI 则按它们自己订阅的方式收到滚轮上报，行为与桌面滚轮完全一致，松手后还有惯性。

**尺寸跟着正在用的那一端走。** 一个 PTY 只有一个尺寸，所以它属于「此刻正在操作的那块屏幕」：在电脑上
操作就用电脑的宽度，拿起手机就换成手机的，切回来再变回去。其余客户端渲染同一个网格，窗口装不下时
横向平移查看。

**布局收得下。** 640px 以下，分屏布局收成单终端，两侧面板改为浮在工作区之上而不再占走一列，控件放大到
手指点得准的尺寸，顶栏右侧的工具收进一个「更多」菜单。

**选目录不再依赖系统对话框。** 浏览器里新建终端原先要弹 `window.prompt`，部分移动浏览器会直接屏蔽它，
导致远程客户端根本建不出终端。现在换成应用内对话框，并预填当前工作空间的目录——那个路径在跑 Termexo
的电脑上，手机本来也无法浏览选择。

## 这次会话到底改了什么，一眼能看到

V0.8 还加了一个会话级的 Git 视图。它跟随当前终端，以**该终端启动时的 HEAD** 为基线：这次会话动过哪些
文件、提交了哪些内容、任意一个文件的单栏或双栏 Diff，以及 +N / −N 的行数。

它会在你停留期间持续读取仓库，不需要手动刷新；切换当前终端或读取失败都不会把你弹回终端视图；读不到时
会说明原因；离开再回来，仍停在原来那个文件、原来那种 Diff 布局上。

原生会话文件始终只读——Termexo 解析它们，但从不改写、重命名或删除。

## V0.8.1：把第一次打开的体验修了

一个尴尬的细节：此前新安装会自动种下三个示例工作空间，目录指向一个谁的机器上都不存在的路径，里面的
Agent 终端还会去恢复根本不存在的 session id。于是新用户看到的第一屏，是两个报 `Invalid session ID`
的终端。

V0.8.1 把它换成了新手引导：从空开始，说明什么是工作空间、头三步做什么、内容都留在本机，并给一个直接
创建的按钮。

同一版还把「新建」从窗口工具栏挪回了标签栏——它只往某一条标签栏里加一个标签，本来就不该摆在工作区级别
的位置；并且新建完会直接打开那个终端，此前从任务看板或 Git 视图新建，终端建好了却不出现。

![V0.8 的桌面工作台：双终端网格与真实命令输出](../assets/termexo-workbench-v0.8.png)

## 一条对外的连接，由你自己打开和关闭

Termexo 一直是本地优先的：没有 Termexo 账号、没有云服务、没有强制同步。工作空间状态保存在本机 SQLite，
API Key 只进 Windows Credential Manager，前端拿不到明文。

远程访问是唯一一条对外的连接，也刻意做成了「你自己打开、自己发令牌、随时能关」的形态。它的实现同样克制：
远程请求不另写一套后端，而是复用桌面端自己的命令表——从 socket 收到的请求被转成 `InvokeRequest` 交给
主 webview，走同样的命令、同样的反序列化。代价是 Tauri 的 ACL 在本地来源下不覆盖应用命令，而这个桥接
必然声称本地来源，所以**显式白名单是唯一的授权边界**：npm 自更新、原生文件读写、以及修改远程访问设置
本身，都被拒绝。

## 该说清楚的边界

- 只有 Windows 版本（Windows 10/11 x64 + WebView2）。没有 macOS 和 Linux。
- 远程访问面向可信网络（家庭局域网或 VPN）。自签名证书会让浏览器提示不安全，每台设备需要手动确认一次。
- **令牌等同于这台电脑上 Termexo 的完整控制权**，可以在你的项目目录里启动 Agent，请不要转发给别人。
- 终端只有一个尺寸，以最后一次调整为准：在手机上打开终端，会同时改变桌面端的列数。
- 任务看板不同步，任务保存在各自浏览器本地。
- Codex 的第三方 Endpoint 需要兼容 Responses API，不承诺所有第三方模型都能接。

## 一条命令体验

```powershell
npx termexo@latest
```

需要 Windows 10/11 x64、WebView2 和 Node.js 18.18+。从源码构建另需 Rust 与 Visual Studio C++ 生成工具。

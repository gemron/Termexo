# Termexo V0.8：在手机浏览器里操作 Windows 上正在运行的 Claude Code 终端

Termexo 是一个 MIT 开源、面向 Windows 10/11 的本地多 Agent 编程工作台，用真实 PTY 同时运行 Claude Code、Codex CLI 和 OpenCode，并在 Workspace 里统一管理终端布局、运行状态、原生会话与模型配置。

V0.8 的主线是**远程访问**：打开之后，同一局域网或 VPN 内的手机、平板、另一台电脑，用浏览器就能进入完整工作台。

![手机通过远程访问打开工作台](../assets/termexo-remote-v0.8.png)

## 1. 远程访问到底做了什么

它不是屏幕镜像，也不是另开一套会话。远程端看到的是**同一批工作空间、同一批终端**，实时读写桌面上正在运行的那一批 PTY 进程：手机上敲的字符进的是同一个进程的 stdin，桌面上的输出同步出现在手机上。

典型用法是：Agent 跑到一半停在「等待授权」，而你已经离开工位——掏出手机确认一下，让它继续跑，而不是等回到桌前。

![V0.8 桌面工作台](../assets/termexo-workbench-v0.8.png)

## 2. 开启步骤

1. 打开 Termexo 的**设置**；
2. 进入**远程访问**；
3. 打开**启用**开关（同一区块里可以设置监听地址与端口，以及是否使用 HTTPS）；
4. 点击**保存并应用**；
5. 用手机扫描面板上的**二维码**，或者复制链接发到目标设备上打开；
6. 首次进入需要输入**访问令牌**，令牌可以在同一面板里直接查看。

默认走自签名 HTTPS，所以浏览器会提示证书不安全，每台设备需要手动确认一次，之后就不再打扰。设置页里监听地址与端口并排显示，复制按钮贴着链接，总开关和 HTTPS 选项分开摆放，并带一个**已连接设备**计数，可以直接看出现在有几台设备连着。

## 3. 令牌的含义与更换

访问令牌是唯一的进入凭证，**它等同于这台电脑上 Termexo 的完整控制权**——拿到令牌的人可以操作你的终端。所以：

- 只在可信网络（家庭局域网或公司 VPN）里开启；
- 令牌只发给自己的设备，不要贴进聊天群或截图里；
- 怀疑泄露、或者临时借出过设备之后，在设置面板里**重新生成令牌**即可，旧令牌立刻作废，其他设备需要重新输入。

另外，远程端有一条硬性限制：**不能修改远程访问设置本身**，也不能导入导出网络配置或触发 npm 自更新。也就是说，即便有人拿到令牌，也无法从远程端给自己扩权或换发令牌。

## 4. 手机端的实际体验

- 屏幕宽度 640px 以下，分屏布局收成单终端；两侧面板浮在工作区之上，不占走一列；
- 控件放大到手指可点的尺寸，顶栏右侧的工具收进一个「更多」菜单；
- **手指拖拽可以滚动终端**：普通缓冲区直接滚，Claude Code、OpenCode 这类全屏 TUI 也能正确收到滚动，行为与桌面滚轮一致，松手后带惯性；
- 新建终端使用应用内对话框并预填当前工作空间目录，不再依赖被部分移动浏览器屏蔽的系统弹窗。

需要注意的是，**一个 PTY 只有一个尺寸**，它属于正在使用的那一端：在电脑上操作用电脑的宽度，拿起手机操作就换成手机的，切回来再变回去；其余客户端渲染同一张网格，窗口装不下时横向平移。所以在手机上打开终端，桌面端的列数会跟着改变。

## 5. 会话级 Git 视图

V0.8 的另一条线是 Git 视图跟随**当前终端**，以该终端启动时的 HEAD 为基线：

- 显示这次会话动过哪些文件、提交了哪些内容；
- 任意文件可看单栏或双栏 Diff，并显示 +N / −N 行数；
- 停留在该视图时持续读取仓库，不用手动刷新；
- 切换当前终端或读取失败都不会把你弹回终端视图，读不到时会说明原因；
- 离开再回来，仍停在原来的文件和 Diff 布局上。

![会话级 Git 视图](../assets/termexo-git-v0.8.png)

原生会话文件（`~/.claude/projects/**/*.jsonl`、`CODEX_HOME/sessions`）始终只读，Termexo 不修改、不重命名、不删除。

## 6. V0.8.1：首次启动改为新手引导

这是最新的一个小版本，改的是新用户的第一屏。

此前新安装会种下三个示例工作空间，目录指向一个谁的机器上都不存在的路径，里面的 Agent 终端还会去恢复根本不存在的 session id——新用户看到的第一屏是两个报 `Invalid session ID` 的终端。现在改为**从空开始**：工作区那块直接说明什么是工作空间、头三步做什么、内容都留在本机，并给一个直接创建的按钮。

同版还有三处整理：

- **「新建」归位到标签栏**：它原先在窗口工具栏里和工作区开关并列，而它其实只是往某条标签栏加一个标签。现在它接管标签栏里的 `+`，Agent 菜单一并带过去，按钮紧跟最后一个标签，菜单里 Agent 排在普通 Shell 上面。
- **新建完直接打开新终端**：此前只设置活动终端，而任务看板和 Git 视图并不画终端，从这两个视图新建时终端建好了却不出现。现在所有主动开终端的入口都会切回终端视图并显出它。
- 远程访问设置页重排（见上文第 2 节）。

## 7. 环境要求与安装

运行环境：**Windows 10/11 x64、WebView2、Node.js 18.18+**。从源码构建另需 Rust 与 Visual Studio C++ 生成工具。

一条命令直接体验：

```powershell
npx termexo@latest
```

也可以全局安装：

```powershell
npm install --global termexo@latest
termexo
```

技术栈是 Angular 22 前端 + Tauri 2 / Rust 外壳，真实 PTY，SQLite 持久化，API Key 只进 Windows Credential Manager，前端拿不到明文。

## 8. 边界，先说清楚

- **仅 Windows**，没有 macOS / Linux 版本。
- 远程访问面向可信网络（家庭局域网或 VPN）；自签名证书会让浏览器提示不安全，需要每台设备手动确认一次。
- **令牌等同于这台电脑上 Termexo 的完整控制权**，请按上文第 3 节管理和轮换。
- 远程端不能修改远程访问设置本身，也不能导入导出网络配置或触发 npm 自更新。
- 终端只有一个尺寸，以最后一次调整为准；手机上打开终端会同时改变桌面端的列数。
- 任务看板不同步，任务保存在各自浏览器本地。
- Codex 第三方 Endpoint 需要兼容 Responses API，不承诺所有第三方模型都兼容。
- 应用退出后被终止的系统进程不会「假装恢复」，历史会话需要在会话中心显式恢复。

Termexo 本地优先：没有 Termexo 账号，没有云服务，没有强制同步。远程访问是唯一一条对外连接，且由用户自己打开、自己发令牌、随时可关。

## 优先级与复现

### P1-01：弹窗未限制键盘焦点，Esc 无法关闭

打开“新建工作区”，聚焦名称，然后连续 Tab：项目目录→选择目录→取消→页面 BODY→后台工作区按钮→终端→任务。后台控件仍能接收焦点。按 Esc，弹窗仍存在。“编辑工作区”也观察到 Esc 不关闭。

应统一弹窗基础行为：打开后定位首个有效控件，Tab/Shift+Tab 在弹窗内循环，关闭后还原触发按钮焦点；无修改时 Esc 关闭，有修改时保留草稿或说明未保存状态。`aria-modal="true"` 本身不能实现这些行为。

定位：`dialogs/create-workspace-dialog.ts:17`、`dialogs/edit-workspace-dialog.ts`。这是本轮对具体弹窗的实测，不意味着已证明所有弹窗都有同样问题。

### P1-02：切换模型 Profile 静默丢失未保存输入

设置→模型 Profile→将 Claude Sonnet 名称改成“未保存草稿-体验审查”→点击 GPT-5.6 Sol→再点 Claude Sonnet。名称恢复原值，没有保存/放弃提示。

切换设置分类再回来能够保留草稿；切换具体 Profile 则会丢失，两者行为不一致。建议为每个 Profile 保存独立草稿，并显示“未保存”；或在离开有修改的 Profile 时提供保存/放弃/继续编辑。

定位：`dialogs/agent-settings-dialog.ts:1527` 的 `editModel`。

### P1-03：手机宽度下设置和交接仍沿用两栏

390×844 下，设置的 Profile 列表占据大量宽度，右侧输入区只能显示截短名称和窄字段，分类也看不到当前“模型 Profile”。交接左栏更宽，正文被挤到约百像素，标题频繁换行，底部终端选择和发送按钮拥挤。

窄屏应改成“选择配置/交接包→查看详情”的单栏导航，或将左栏移入抽屉；分类用可见当前项的选择器；操作区固定且不与字段重叠。桌面双栏可以保留。

证据：[模型设置 390](settings-model-390.png)、[交接 390](handoff-390.png)。手机截图只证明前端适配问题，不证明远程服务连接状态。

### P1-04：提示词筛选直接暴露翻译键

打开提示词资产库，筛选项显示 `prompt.filter.all`、`prompt.filter.draft`、`prompt.filter.history`、`prompt.filter.favorite`、`prompt.filter.pinned`。

应补齐“全部、草稿、历史、收藏、置顶”等翻译，并检查其他语言的回退。不要让翻译键进入产品界面。

证据：[提示词资产库](prompts.png)。定位：`dialogs/prompt-library-dialog.ts:176` 动态生成筛选键；`core/i18n/i18n.service.ts`。

### P2-01：长表单缺少固定保存区域

1440×900 的模型设置也需要滚动才看到保存。720×480 下，“保存 Profile”初始 top 约 1014，窗口高 480；滚动后能到达，并非按钮完全不可用。滚动到底时标题/关闭入口也不再完整可见。

建议标题与分类固定，内容区独立滚动，底部固定“保存/取消/未保存”区域。未启用的 CLI 配置折叠成一行，余量告警等低频选项放到高级设置。网络表单采用相同框架。

证据：[模型首屏](settings-2.png)、[最小窗口](settings-minimum-720.png)、[滚动后](settings-minimum-scrolled.png)、[网络首屏](settings-4.png)。

### P2-02：新建 Agent 流程多一个目录确认，诊断出现太晚

现有工作区已经有目录，但浏览器预览中新建任一 Agent 都先弹目录确认，再进入会话配置；进入配置后才看到不可启动的诊断。

建议直接进入启动配置，默认当前项目目录，在同一页提供“更改”；先显示 Agent 可用性与下一步。对浏览器预览应提供“此环境不支持”的准确说明，避免“去安装”让用户误以为浏览器内可完成安装。桌面原生目录选择器本轮未验证。

证据：[目录步骤](launch-claude.png)、[Claude 配置](launch-claude-options.png)、[Codex 配置](launch-1.png)。

### P2-03：只有一个模型/账号时，切换页是死路

模型切换页只有禁用的当前模型和禁用的执行按钮。账号页提示先去设置添加，但没有跳转入口。

增加“添加模型配置”“添加登录账号”按钮，直接打开对应设置分类；返回时保留原终端上下文。现有重启、新会话影响说明应保留。

证据：[模型切换](model-switch.png)、[账号切换](account-switch.png)。

### P2-04：工作区悬停操作遮盖被操作对象

鼠标移入侧栏行时，上下移、编辑、删除、收藏占据行右侧，“Termexo”缩为“Terme…”且分支截断。自动化悬停到该行中心还观察到 `workspace-actions` 拦截指针。

建议常驻一个更多菜单，收藏可单独保留；排序改为拖动或菜单项。删除不必与高频切换入口挤在同一行。

证据：[侧栏悬停](workspace-hover.png)。定位：`workspace/workspace-sidebar.html`、`.scss`。

### P2-05：窄桌面四列任务卡片过小，手机状态切换成本高

1024 宽时侧栏约占 210 像素，余下宽度分给四列，长任务标题换成多行，目录和按钮都很紧。390 宽已提供横向滚动，因此不是页面横向溢出；但查看“已验证”要横移多列。

建议桌面窄窗自动收起工作区侧栏或保持合理列宽后横滚；手机提供“待办/执行中/待验收/已验收”状态切换。当前“已完成/已验证”与副标题“等待人工验收/归档”的含义可统一得更直观。

证据：[1024 看板](tasks-1024.png)、[390 看板](tasks-390.png)。

### P2-06：MCP 缺少前端 JSON 校验和错误定位

填写名称及 `{invalid`，点击保存，预览侧栏出现新 Profile，未显示错误。CodeGraph 返回的 `AgentService.saveMcpProfile` 证实浏览器分支直接 upsert；本轮没有验证桌面后端是否拒绝。

建议输入时检查 JSON 语法、标出位置，保存前给出字段内错误，提供最小有效示例和格式化。更深层的 MCP 配置检查仍需后端验证。

证据：[非法 JSON 保存后](mcp-validation.png)。定位：`dialogs/agent-settings-dialog.ts:1673`、`core/services/agent.service.ts:438`。

### P2-07：预览和空状态没有统一表达能力边界

主界面演示终端写“运行中”，账号写“已登录”，诊断却显示 CLI 不可用。Git 长期显示“正在检测 Git 仓库”；远程访问把“仅桌面应用可用”包装成读取失败并提供重试。会话中心在预览空态引导安装 CLI/扫描记录。

应在预览环境常驻说明，并把“不支持、未配置、加载中、失败、无数据”分开；确定不支持时给出可行下一步，不显示无效重试或持续检测。不要将本条理解为桌面诊断真的失败。

证据：[诊断](01-diagnostics.png)、[登录账号](settings-1.png)、[远程错误态](settings-5.png)、[会话中心](sessions.png)。

### P2-08：交接包上下文不足时仍显示一般成功态

从预览终端生成包后出现“交接包已生成”，内容主要是 `Continue Termexo`、`Handoff from 1 active agent terminal.` 及“暂无记录”。界面缺少补充目标/下一步的编辑入口，仍提供发送并继续。

建议显示上下文来源与完整度；缺任务和会话记录时提示先补充目标，允许编辑目标和下一步；发送前让用户看清接收终端及会发送的内容。真实桌面数据充分时的生成质量未验证。

证据：[生成后交接包](handoff-generated.png)。

### P2-09：诊断文案和信息层级落后于当前功能

诊断显示 Claude、Codex、OpenCode、Antigravity 四张卡，但按钮仍写“重新检测两个 CLI”。上部卡片与下方“未找到”列表重复，让应用更新区域进入滚动区。

按钮改为“重新检测所有 Agent”，每个 Agent 用一行呈现状态、版本和修复入口，详细路径按需展开。统一“工作区/工作空间/Workspace”“模型 Profile/模型配置”等名称。

证据：[诊断](01-diagnostics.png)。定位：`core/i18n/i18n.service.ts:1345`。

## 建议实施顺序与验收

1. 先修 4 项 P1：键盘焦点、Profile 草稿、手机两栏、翻译键。验收用上述可复现路径；焦点要包括反向 Tab 和关闭后焦点还原。
2. 再统一弹窗标题/内容/底部操作布局；在 1440×900、1024×768、720×480 和 390×844 检查。滚动时保存与关闭仍应可发现，字段不能被按钮遮住。
3. 简化新建与配置流程，补账号/模型的直达入口；让预览能力说明和各种空态一致。
4. 最后补真实桌面验收：Agent 启动/切换/重启、任务执行至人工验收、原生会话恢复、Git 变更与差异、远程正常连接/错误恢复、存储管理。上述范围当前仍未完成，不能作为发布通过依据。

未观察到需要推倒重做的整体结构问题。任务的“仅创建/创建并执行”和折叠执行设置、CLI 安装计划、合并影响说明已有明确的操作层级，优化时建议保留。

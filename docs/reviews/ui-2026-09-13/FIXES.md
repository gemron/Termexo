## 第二轮：统一设置草稿（用户“继续”后）

已将第一轮的模型草稿逻辑提取为窗口内共用的 `ProfileDrafts`，接入账号、MCP 和网络配置，避免四套保存规则分化。

- 切换配置、切换分类和刷新账号状态时，未保存输入保留。尚未填写完整、语法不合法的 MCP JSON 也作为草稿保留。
- 四类编辑区均显示“未保存”。关闭设置检查全部配置草稿，提供继续编辑或放弃；保存一个配置不会清除另一个配置的草稿。
- 成功回执才确认保存。未收到成功回执时保留输入；即使新配置使用默认值、未改任何字段，首次创建失败也不会被当作已保存。
- 保存回执按字段合并：清除已提交的密码/API Key 输入，同时保留保存期间新输入的字段。网络凭据“已保存”状态在成功前不再提前变化。草稿凭据只在内存中保留，不写入浏览器存储。
- 四类保存共用忙碌状态和回执流程，保存期间禁止关闭；确认条上的放弃按钮也遵守忙碌限制。
- 网络表单存在未保存修改时禁用“测试连接”，提示“请先保存修改，再测试连接”，防止误测旧配置。
- 删除的配置会清除其草稿，避免已经删除的内容继续触发关闭警告。

验证：完整前端测试 **53 个文件、436 项通过**；生产构建及 `git diff --check` 通过。首包约 1.54 MB，体积警告仍在既有阈值下，未调整预算。设置代码继续按需加载。

真实浏览器已操作账号切换/保存、MCP 新建草稿往返、网络配置切换/保存及测试按钮禁用与恢复；390px 下关闭提示和底部操作区仍可见。浏览器测试数据已放弃或刷新清理，未执行本机登录或网络连接测试。失败/保存期间输入的边界由组件测试覆盖，未冒充桌面故障注入验证。

## 第三轮：交接保存与侧栏操作（再次“继续”后）

- 交接页增加“保存修改”和未保存标识，保存更新原历史记录；关闭、切换历史、重新生成、导入或删除当前记录前，未保存修改均有继续编辑/放弃提示。
- 发送流程先保存当前交接，再向终端发送。保存和发送期间锁定编辑与离开操作；保存失败保留输入和原记录。保存继续执行脱敏和 Token 预算处理，导入包的历史记录仍归属导入工作区。
- 修复切换工作区后再次打开交接页时，预览可能沿用上一工作区内容的问题。
- 侧栏“活动 Agent”改为准确的“工作区终端”，包含普通终端和已停止会话；点击行可直接切换终端。Git 信息不可用时，变更数显示“—”，避免误读为零变更。
- 工作区创建/编辑页明确“默认终端目录”，创建页说明新终端与任务项目目录的关系；项目弹窗补充其所属工作区与目录作用。
- 390px 下未保存提示的说明独占一行，两个操作按钮并排；保存操作、历史导出和发送区保持可见。

验证：完整前端测试 **55 个文件、445 项通过**；生产构建和 `git diff --check` 通过。新增测试覆盖离开保护、历史切换与导入保护、脱敏保存、成功回执、保存期间锁定、预览存储失败、删除后不重建、导入归属和侧栏终端选择。

浏览器实际完成：编辑目标/下一步 → 保存 → 关闭 → 刷新 → 从历史恢复；未保存历史切换/关闭/Esc；跨工作区打开交接；侧栏点击切换终端。复核 1440×900、720×480、390×844；窄屏交接无横向溢出，保存和发送区均在弹窗内。两条测试交接记录已通过界面删除，创建工作区表单未提交。未向真实 Agent 发送内容，原生保存及发送链路仍需桌面验证。

构建首包约 **1.55 MB**（实际约 1,546.63 kB），仍低于 1.55 MB 硬限制，但超过 1.45 MB 警告阈值；既有两项样式体积警告仍在，未调整预算。

# Termexo 界面布局、交互与视觉评审（2026-09-14）

> 本轮只评审，没有修改源码。上一轮（[2026-09-13](../ui-2026-09-13/README.md)）主要检查流程、键盘操作和草稿保护，相关问题已经修复；本轮重点检查布局、信息层级、视觉一致性和交互设计，并做了一次设计系统静态审计。

## 结论

5 路评审共提出 89 条问题，合并同根因后剩 **67 条：P1 10 条、P2 40 条、P3 17 条**。

整体结构不需要推倒重来，问题主要集中在三处：

1. **跨界面的公共部分没有统一实现。** 状态表达、错误反馈、焦点样式、弹窗行为、多语言各自为政，同一个问题会在 4～5 个界面里分别出错。
2. **设计令牌只覆盖了颜色。** 间距、字号、圆角、阴影、按钮各写各的，所以视觉松散，字号也普遍偏小：可见文字里 84% 在 11px 以下。
3. **几个大组件承担的职责太多。** `app.ts` 有 3,826 行，设置弹窗 2,104 行，任务看板的 ts 和 html 合计 2,000 行以上。上面那些不一致，很多就出在这里。

10 条 P1 里大部分是 S 级工作量，建议先修。其中两条会被用户直接看到，而且现有测试已经暴露出来：

- 仓库自带的 `npm run e2e:responsive` 目前卡在手机视口断言上，失败原因就是 P1-01。
- 会话中心的状态显示错误（P1-10），属于功能缺陷。

## 二、系统性问题（跨界面，建议整体修）

### S-1 状态语义没有唯一来源（P2 · M）

来源：SHELL-05、TERM-04、DS-05、INSP-01、TASK-04、DS-14

| 状态 | 现在的表现 |
| --- | --- |
| 等待授权 | 横幅红色「等待授权」，标签页黄色，通知和 Agent 侧栏橙黄色「需要确认」，顶栏写「等待」 |
| 等待输入 | 圆点蓝色、文字和顶线琥珀色，同一个头部里两种颜色语义 |
| 被限流 | 头部渐变黄色，状态灯和标签红色；标签页的警告组和错误组都写了它 |
| 启动中 | 用警告黄，和「需要确认」同色 |
| 运行中 / 思考中 / 已完成 | 三种很接近的绿；检查侧栏里「运行中」用的是主色 |
| 失败 | 7px 红点加灰色常规字重，看起来比「已完成」（绿顶线、绿底、粗体）还弱 |
| 已停止 / 已断开 | 同一种灰，分不开 |

其他问题：
- 看板用红、橙、蓝表示优先级，和运行状态的颜色冲突。
- 检查侧栏里「工具调用失败」和「工具调用开始」是同一个蓝色图标。
- 同时有 14 个无限循环动画在跑。
- 状态映射在 CSS 里写了 3 份（`app.scss:765-830`、`terminal-panel.scss:195-250`、`inspector-panel.scss:406-445`），TS 标签表写了 4 份，还有一份 `TERMINAL_STATUS_LABELS` 是死代码。

**建议：** 在 models 里建一张 `TERMINAL_STATUS_META`，字段为 tone、labelKey、icon、animated。tone 分五类：
- 进行中（启动中、运行中、思考中）
- 需要处理（等待输入、等待授权），琥珀色
- 异常（失败、被限流、已断开），红色；失败要加粗、加底色
- 完成，绿色
- 中性（空闲、已停止），灰色

模板只输出 `data-tone`，由全局 `.tone-*` 样式取主题色。标签页、面板、横幅、通知、检查侧栏共用这张表，同一个状态只用一个词。只有需要处理的状态闪烁，并限制循环次数。优先级改成中性文字标签。

截图：`terminal/status-matrix-1920.png`、`shell/attention-banner-approval-1440.png`、`tasks/inspector-bottom-1440.png`

### S-2 字号过小，字重层级是假的（P2 · 令牌 M，迁移 M/L）

来源：DS-04、TERM-09、SET-07、GIT-01、TASK-03、SHELL-14

**字号**
- 一共 12 种取值；9px 及以下 108 处（30%），11px 及以下占 84%。
- 主界面 69% 的可见文字在 11px 以下；诊断页 38 段文字里有 28 段在 10px 以下。
- 看板元信息 9px，Git 标签 7～8px，终端的 AUTO 标记 8px，设置里的提示和错误 9px。

**字重**
- 声明了 13 种字重，但字体栈首选 Microsoft YaHei UI，又设置了 `font-synthesis:none`（`termexo-theme.css:90`）。实测只渲染出常规和粗体两种字形，560、580、620、650、680 这些层级实际不存在。

**对比度**
- `--text-muted` 放在浅色底上只有 4.44:1。

**建议：** 字号令牌定为 10（只给徽标和代码元信息）、11（提示、错误、次要文字）、12、13、15、17；提示和错误不低于 11px。字重只保留 400 和 600 两档，行高保留 1.2、1.4、1.55 三档。迁移后在 720×480 和 1024×768 回归检查信息密度。

### S-3 设计令牌只有颜色（P2 · 令牌 M，迁移 L）

来源：DS-06、DS-05、TERM-15、SHELL-14、TASK-11

| 维度 | 现状 |
| --- | --- |
| 间距 | 不在 4/8/12/16/20/24/32/40 刻度上的有 546/858 处（63.6%），其中奇数像素 299 处 |
| 圆角 | 26 种；写死的像素值有 14 种（3px 12 次、5px 11 次……） |
| 阴影 | 55 种，其中弹窗阴影 7 种 |
| z-index | 15 种，从 1 到 1200；看板弹窗是 1200，高于 Toast 的 120 |
| 其他 | 动画时长 22 种，断点 12 种，按钮高度 17 种 |
| 颜色 | 5 对同色异名变量（例如 `--accent` 和 `--color-primary`）；写死的颜色 92 处，其中 todo-board 44 处；Git 状态色和优先级色各有一套平行色板 |

**建议：** 在共享主题文件 `termexo-theme.css` 里增加以下令牌：
- 间距 `--space-*`
- 圆角：sm 4、md 6（输入框、按钮）、lg 8（卡片）、xl 12（弹窗）
- 阴影：popover、dialog 两档
- z-index：sticky 10、panel 30、popover 60、dialog 100、嵌套弹窗 110、Toast 120、gate 200
- 动画时长：fast、base、slow 三档

同时删除同色异名变量，用 stylelint 的 `declaration-strict-value` 阻止新增字面量。迁移从弹窗层开始，配合 S-6 一起做。

### S-4 装饰过重（P3 · S）

来源：DS-14、SHELL-13、TERM-15、TASK-11

- 普通内容区也加了浮起阴影：顶栏、标签栏、终端面板、任务卡片、全局 `.card`。
- 13 层发光、10 处渐变、文字发光，按钮悬停时还会上移 1px。
- blur 策略自相矛盾：`agent-dialog.scss:9-11` 的注释说为了 WebView2 性能已经去掉 blur，但 11 个弹窗共用的 `dialog.scss:9` 仍然是 `blur(10px)`。

**建议：** 内容区只用背景加边框，阴影只留给浮层、弹窗和 Toast；遮罩统一去掉 blur；激活中的终端只保留一条描边。

### S-5 按钮体系三套并存（P2 · M）

来源：DS-07

- 262 个按钮里，74% 没有使用 `btn` 类。
- 主按钮有 3 套实现：DaisyUI 的 `.btn-primary`、组件里的 `.primary`、看板的 `.primary-action`。有 7 个弹窗同时写了 `primary btn btn-primary`，最终外观取决于层叠顺序。
- 危险按钮有 6 种写法；看板用的红色 `#e06c75` 和主题错误色 `#ee6f61` 不一样。
- busy 状态下的禁用行为不一致，所以出现了 P1-06 里的第 ③ 点。

**建议：** 只保留 DaisyUI `btn` 加变体，统一尺寸令牌（sm 28px、xs 24px）。也可以提供一个 `button[txButton]` 指令，带 variant、size、busy 三个输入，busy 时自动禁用并显示加载。

## 四、结构重构建议

以下拆分方案来自读代码后的分析，还没有试拆验证。建议和前面的修复一起分步推进，不要单独做一次大重构。

- **`app.ts`（3,826 行）**
  - 现状：注入了 17 个服务，约 60 个 signal；没有 `app.spec.ts`；e2e 脚本通过 `ng.getComponent` 读取 App 的内部成员，拆分时要保留转发或同步修改脚本。
  - 顺序：
    1. `ToastService`，同时修掉 P1-02
    2. PromptDelivery
    3. Layout
    4. TaskDispatch
    5. LaunchCoordinator。四个启动方法约 211 行结构相同，其中 Claude 那一份漏了安装检测
    6. SessionRestore。要保住 initialize 的执行顺序
    7. ProfileSwitch。回滚逻辑没有测试，先补 spec
    8. 设置宿主
  - 目标：App 最终剩 900～1,000 行，只负责组装。
- **`agent-settings-dialog.ts`（2,104 行）**
  - 现状：四类配置各有一套几乎相同的 24 个方法。
  - 顺序：诊断面板 → 草稿逻辑提成纯函数 → 泛型 `ProfileEditorState<T>` 加 `SettingsDraftStore` → 四个配置面板 → `CliManagerPanel`。
  - 高风险：`@switch` 切换分类时会销毁子组件，所以草稿必须放在 Store 里；评审反馈项目没有引入 zone.js，而视图目前靠普通字段加 `Object.assign` 驱动，拆成子组件之前要先改成 signal；spec 里有 90 处访问内部成员，需要改写。
  - 和 SET-04、S-6 一起做。
- **`remote-access-panel.ts`（1,014 行）**
  - 顺序：纯函数 → `RemoteAccessStore.runAction`，统一 5 处「忙碌 → try → finally」 → 服务、中继、访问地址三个子组件。
  - spec 只做 DOM 查询，风险较低。和 SET-05 一起做。
- **任务看板**
  - 顺序：业务规则移到 `todo.models.ts` → FeedbackDialog，顺带修掉 P1-05 → ProjectDialog 加 DirectoryField → TaskEditorDialog → 套用弹窗骨架 → TodoCard / TodoColumn。
  - 完成第 2～4 步后，样式约降到 15.7 kB，警告消失。和 TASK-03、05、07、08 一起做。
- **`terminal-panel.ts`（1,274 行）**
  - 参照现有的 `TerminalCompositionAnchor`，抽成控制器类：事件监听的 disposer 工具、链接、剪贴板、滚动与触摸、尺寸。
  - 组件本身没有测试，每抽一个控制器之前先补测试。
- **检查侧栏**
  - 5 段重复的折叠头部抽成 `InspectorSectionComponent`；余量区块单独拆出，计时器只在区块展开时运行。

## 六、做得好、应保留

- **外壳**
  - 桌面各宽度下，侧栏头、标签行、Agent 侧栏头都是 44px 高，底边对齐；所有视口都没有页面级横向滚动。
  - 工作区最大化时，开关禁用并说明原因，还提示可以按 Shift+Esc 恢复。
  - 四个工作区弹窗结构一致；删除弹窗写明会停止多少个进程；合并弹窗有合并后数量的预览。
- **终端**
  - 四个启动弹窗共用 `LaunchDialogShell`。
  - 回车提交时会避开输入法选词。
  - 启动过程中主按钮显示「正在启动…」并锁定关闭。
  - 终端区所有纯图标按钮都有可访问名称。
  - 手机快捷键用倒 T 布局，按键 48×40，按键不抢焦点。
- **设置**
  - 远程访问、存储、远程入口页的语言包 7 种语言齐全。
  - 重新生成令牌、断开中继用页内确认，按钮文字是明确的动词。
  - 服务和中继状态都是「圆点 + 颜色 + 文字」。
  - 固定保存区、未保存标记、MCP JSON 即时校验都没有回退。
  - 二维码始终白底黑码，保证能扫。
- **任务和工具**
  - 拖动时只高亮合法的目标列，并提示放下后会发生什么。
  - 卡片删除有行内确认，执行中的任务写「终止并删除」。
  - Git 的读取中、失败、二进制、截断、历史被改写这些状态都有处理。
  - 会话中心的搜索框说明了能搜什么，空状态区分「无匹配」和「预览环境」。
  - 交接在窄屏下切成两个面板。
- **设计系统**
  - 主题色先写 hex，再用 `@supports` 升级到 `color-mix`，并和中继控制台共用。
  - 图标基本统一走 `app-icon`，没有 emoji 或文字符号当图标。
  - 全局处理了「减少动态效果」设置。
  - `appModal` 焦点指令和固定保存区已经可以复用。
